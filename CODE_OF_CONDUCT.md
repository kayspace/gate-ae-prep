# Code of Conduct

## Our Commitment

gate-ae-prep-tracker is a project built for students preparing for GATE Aerospace Engineering. It is maintained currently by myself and exists to be genuinely useful to the people who use it.

Everyone who participates in this project — whether by contributing code, reporting bugs, discussing ideas in issues, or reviewing pull requests — is expected to treat others with respect and to engage in good faith.

This Code of Conduct describes the standard of behavior expected in all spaces associated with this project, and explains what happens when that standard is not met.

## Scope

This Code of Conduct applies in all project spaces, including:

- GitHub Issues
- GitHub Pull Requests and code review comments
- GitHub Discussions (if enabled)
- GitHub Security Advisories
- Any other communication channel directly associated with this project

It applies to all participants: contributors, maintainers, issue reporters, reviewers, and anyone else interacting in these spaces. It applies regardless of experience level, background, or role.

---

## Expected Behavior

Participation in this project should be characterized by the following:

**Respect.** Treat everyone in the project with basic courtesy. Disagreements about code, design decisions, or direction are normal and healthy. Disagreements about the worth or character of a person are not.

**Clarity and good faith.** Communicate clearly and assume good intent from others unless there is clear evidence to the contrary. If a message is ambiguous, ask for clarification before responding negatively.

**Constructive feedback.** When reviewing code or commenting on proposals, focus on the work. Explain what you think should change and why. Critique should be specific, actionable, and professional.

**Acknowledgement of mistakes.** If you are wrong, say so. If you have been corrected, accept it without defensiveness. Everyone makes mistakes; the response to a mistake matters more than the mistake itself.

**Patience with beginners.** This project welcomes first-time contributors. If someone asks a question that seems basic, answer it directly or point them to the right resource. Do not make people feel unwelcome for not knowing something.

**Staying on topic.** Keep discussions relevant to the project. GitHub Issues exist for bug reports, feature requests, and technical discussion. They are not the place for off-topic debates.

---

## Unacceptable Behavior

The following behaviors are not tolerated in any project space:

**Harassment.** This includes persistent unwanted contact, deliberately targeting someone with repeated critical or hostile messages, and any behavior intended to make another person uncomfortable or unwilling to participate.

**Personal attacks.** Criticizing a person rather than their work. Insults, contemptuous dismissal, and condescension directed at individuals rather than ideas are not acceptable.

**Discriminatory language or conduct.** Comments or behavior based on someone's age, disability, ethnicity, gender identity, level of experience, nationality, personal appearance, race, religion, or sexual orientation are not acceptable.

**Deliberate misinformation.** Providing intentionally incorrect technical information to mislead other contributors or users.

**Publishing private information.** Sharing someone's personal information — email address, location, employer, or any other identifying detail — without their explicit consent.

**Disruptive behavior.** Deliberately derailing conversations, flooding issues or pull requests with off-topic content, or otherwise interfering with the normal operation of the project.

**Sustained negativity.** Repeatedly raising objections that have already been addressed, relitigating closed decisions without new information, or engaging in a pattern of unconstructive criticism that slows the project without improving it.

## Reporting a Violation

If you observe behavior that violates this Code of Conduct, or if you have been subjected to such behavior, please report it.

**How to report:**

Contact the maintainer directly through GitHub by sending a message to [@kayspace](kayzspace@outlook.com). If you are reporting behavior by the maintainer themselves, you may note this in your message and it will be handled accordingly.

**What to include:**

- A description of what happened
- Links to the relevant issue, pull request, or comment (if applicable)
- The date and time (approximate is fine)
- Any additional context that would help understand the situation

**Confidentiality:**

Reports are handled confidentially. The identity of the person reporting will not be disclosed to the person being reported without consent.

Do not post public accusations or call-outs in issues or comments. Doing so makes fair investigation more difficult and can cause harm before the facts are understood. Report privately; let the process work.

---

## What Happens After a Report

1. **Acknowledgement.** The maintainer will acknowledge receipt of the report within 72 hours.
2. **Review.** The reported content will be reviewed. If the situation is unclear, the reporter may be asked follow-up questions.
3. **Decision.** A decision will be made based on the facts and the standards described in this document. The reporter will be informed of the outcome.
4. **Action.** If a violation is confirmed, one or more of the enforcement actions described below will be applied.

The goal is to address genuine violations promptly and fairly, not to punish people for honest misunderstandings. Context matters.

---

## Enforcement

Violations of this Code of Conduct are handled with responses proportional to the severity and pattern of behavior.

**Warning.** For a first or minor violation, the person will receive a private or public warning explaining what behavior was problematic and what is expected going forward.

**Temporary restriction.** For repeated or more serious violations, the person may be temporarily prevented from commenting on issues or pull requests, or from having contributions accepted.

**Permanent ban.** For severe violations or a pattern of behavior that does not change after warnings, the person will be permanently blocked from all project spaces.

In cases of immediate, severe harm — such as harassment, hate speech, or the sharing of private information without consent — a ban may be applied without prior warning.

---

## Appeals

If you believe an enforcement action was applied incorrectly or unfairly, you may appeal by contacting the maintainer through GitHub with a description of why you believe the decision should be reconsidered. Appeals will be reviewed once. The maintainer's decision following an appeal is final.

---

## A Note on Intent

This Code of Conduct is not a set of procedural rules designed to catch people on technicalities. It reflects a simple expectation: that everyone who participates in this project engages with honesty and treats others as they would want to be treated.

If you contribute in that spirit, you will never need to think about this document again.
